## 2. 구조 — 표지 + 면 3 + 경첩 감옥

```
 표지            면 1 (프롤로그·1막)      면 2 (2막)            면 3 (3막·피날레)
┌────────┐   ┌──────────────────┐   ┌──────────────┐   ┌────────────────────┐
│ 「나라카」│ → │ 마녀 사무소 · 금고  │ ╲ │ 간판 거리 ·   │ ╲ │ 호박밭 · 카페 본관 · │
│  명패   │   │                  │감옥│ 마녀의 집     │감옥│ 광장(액자)           │
└────────┘   └──────────────────┘ 5 └──────────────┘ 10└────────────────────┘
                                                          (면 3 안 감옥 빗금 15)
```

- 면은 아코디언처럼 접혀 있고, 이웃 면과 경첩으로 이어진다. 현재 면은 정면, 지나온 면은 옆으로 접혀 실루엣만 남는다.
- **경첩 = 감옥.** 감옥 모델 하나를 경첩 두 곳과 면 3 안, 총 세 번 쓴다. 빗금만 5→10→15로 바뀐다. 면 3의 감옥엔 선배들이 화투를 친다.

정보 9개(공간 8 + 표지)가 현재 홈·서브 페이지 전부를 덮는다. 새 페이지는 만들지 않는다.

## 3. 연출

### 3-1. 스크롤 타임라인 (면당 100vh × 3 + 표지)

```
로드 직후   표지 → 자동 1회 열림 (1.2초): 표지 회전 + 면 1 판들이 뒷배경→건물→인물 순으로 일어섬
스크롤 0~   면 1 정지 상태. 명패 3개(사무소·금고·휴게실) 떠 있음
면 전환 구간 현재 면이 반대로 접히며(판들이 눕고) 다음 면이 열림. 경첩 감옥은 두 면에 걸쳐 남고 빗금이 늘어남
면 3 이후   책 아래로 계속 스크롤 → 기존 달력 섹션·새 소식·오시는 길 (HTML, 3D 밖)
```

- 면 안에서 스크롤은 카메라를 움직이지 않는다(면은 정지 무대). 스크롤은 **면 전환에만** 쓴다. 이유: 판 위의 명패가 흔들리지 않아야 누를 수 있다.
- 정지 상태에서 판들은 아주 느리게 호흡한다(±0.3°, 6~8초 주기). 종이가 숨 쉬는 정도.

### 3-2. 빨려들어감 (명패 클릭)

```
명패 클릭 → 카메라 돌리 인 0.9초 (easeInOutCubic) → 방 안 정지 → 정보 패널 슬라이드 인
닫기·뒤로·Esc·다른 명패 → 돌리 아웃 0.6초 → 면 정면 복귀
```

- 방은 **터널북**: 판 5겹 이상을 앞뒤로 세운다 — 앞 액자(문틀) · 인물 · 가구 · 뒷벽 · 창밖. 카메라가 들어가면 겹 사이 시차로 깊이가 생긴다.
- 정보 패널은 HTML(`home-paper` 시트)이며 3D 위에 겹친다. 패널 안에 "더 보기" 링크가 목적지(§2-1)로 간다.
- URL: 방에 들어가면 `/#room=office` 처럼 해시를 남겨 뒤로 가기와 공유가 된다.

### 3-3. 첫 화면 (Q6)

```
┌──────────────────────────────────────────┐
│ 나라카        달력·출근표   인스타          │ ← 상단 바: 항상 고정, 3D 밖 (기존 HomeHeader)
│        [면 1: 마녀 사무소 · 금고]           │
│         경첩 감옥(빗금 5)                   │
│     ▢ 사무소   ▢ 금고   ▢ 휴게실           │ ← 명패(HTML 버튼, 판 위에 얹힘)
│  대구 동성로 요괴 컨셉카페 —                │ ← 태그라인, 하단
│  사고 치다 붙잡힌 요괴들이 일합니다          │
└──────────────────────────────────────────┘
```

원칙: **손님이 진짜 필요한 것(이름·언제 여나·인스타)은 3D 뒤에 숨기지 않는다.** 상단 바와 하단 태그라인이 그것을 항상 들고 있다.

### 3-4. 모바일(세로)

- 카메라를 더 가까이 두어 면이 화면 폭에 맞고, 판들이 위로 높게 일어서 세로 여백을 쓴다.
- 명패는 화면 하단에 가로로 나란히(터치 타깃 44px 이상).
- 자유 회전·드래그 없음. 데스크톱도 동일(마우스 위치에 따른 ±2° 시차만).

## 4. 컷아웃 결과 에셋 (Q5)

### 4-1. 결

| 대상 | 소스 | 결 | 이유 |
|---|---|---|---|
| 무대 — 지형·건물·가구·소품·표지 | 힉스필드 이미지 생성 | 앤틱 레트로 (다크 오크 #1A0F07·앤틱 골드 #C8B16B·양피지 #EBDFB6·레드 래커 #A41010) | 캐릭터가 아니라 일관성 문제 없음, 사이트 팔레트와 일치 |
| 인물·펫 | 원화 17장 + 릴스 신규컷 A~E에서 오려냄 | 치비(작가 원화) | 일관성·AI 느낌 문제를 원화가 막음 |

두 결의 통합: **종이 인형 처리** — 모든 컷아웃에 같은 흰 종이 테두리(2~3px), 같은 종이 질감 오버레이, 같은 접촉 그림자. 앤틱 무대 위 치비 종이 인형이 팝업북의 문법이 된다("앤틱 메인 + 치비 포인트" 결정과 일치).

### 4-2. 에셋 목록 (약 80장, 전부 WebP 투명)

| 구분 | 수 | 내용 |
|---|---|---|
| 표지 | 2 | 가죽 표지(금박 「나라카」 자리 비움), 명패 |
| 면 뒷배경 | 3 | 밤하늘·안개·먼 지붕 실루엣 (면당 1) |
| 지형·길 | 3 | 면당 바닥판 1 |
| 건물 외형 | 7 | 사무소·금고·간판 거리 건물열·마녀의 집·카페 본관·광장 액자·감옥(1개, 빗금 3종 텍스처) |
| 방 내부 겹 | 8방 × 5 = 40 | 앞 액자·가구·뒷벽·창밖·소품 (인물 겹은 원화) |
| 소품 | ~10 | 나무·가로등·호박 덩굴·물대포·솥·우편함 등 |
| 인물·펫 컷아웃 | ~15 | 옥자(앉음·서 있음·잠), 멜(운다·걸레), 바나(먼지떨이·침 삼킴), 미호(노래·설거지), 주방요괴, 유령, 시온·코코·규종·선아·수아, 단체샷 |

글자는 그림에 넣지 않는다. 「나라카」 간판·「@naraka_concafe」 명패도 HTML 텍스트를 판 위에 얹는다(생성 한글 깨짐 방지·문안 수정 가능).

### 4-3. 파이프라인

```
무대: 힉스필드 generate_image (앤틱 프롬프트, 단색 배경) → remove_background → 종이 인형 처리(PIL) → WebP
인물: 원화 PNG → 경계색 팔레트 BFS 추출(릴스 때 확립: 먹선은 채색면 7px 이내 유지·최대성분) → 종이 인형 처리 → WebP
검수: 8장씩 한 판에 모아 결 비교 → 튀는 것만 리테이크
```

이미지→3D·Blender 단계는 없다. 경첩 각도·겹 간격은 코드 상수(§5-2).

### 4-4. 전제

- **작가 웹 사용 동의** — 인물을 홈에 상시 노출하므로 필수. 사장님이 작가님께 확인. 동의 전에는 인물 자리를 실루엣 판으로 두고 무대만 먼저 만든다.
- 원화에 없는 앵글은 만들지 않는다. 없으면 그 자리를 소품으로 채운다.
- 캐논 준수: 등장인물 4 + 주방요괴 + 방문자, 펫 6. 새 인물 금지. 금지 어휘 목록으로 문안 grep 검수.

## 5. 기술 설계

### 5-1. 스택·경계

- `three` + `@react-three/fiber` + `@react-three/drei`(`useTexture`, `Html` 최소). 새 의존성 3개. 홈 `/`에서만 `next/dynamic({ ssr: false })`로 로드.
- 렌더는 판(plane) + 텍스처만. 조명 없음(`MeshBasicMaterial`), 그림자는 텍스처에 구워 둔 것. 폴리 수는 사실상 0.
- 3D는 **장식과 내비**만 담당한다. 정보(정보 패널·명패·상단 바·달력)는 전부 HTML이며 서버 컴포넌트가 내려준다. 3D가 죽어도 정보는 남는다.

### 5-2. 컴포넌트·데이터

```
src/lib/homeBook.ts              면·공간·판 정의 (데이터, 서버/클라이언트 공용)
  export const BOOK_PAGES: BookPage[]     // 면 3개: id, act, rooms[], layers[]
  export const BOOK_ROOMS: BookRoom[]     // 공간 8개: id, pageId, label, href, layers[], cameraIn
  type Layer = { src, w, h, x, y, z, hinge?: "bottom"|"left"|"right", open: number /* 0~1 등장 시점 */ }

src/components/home/book/PopupBook.tsx      캔버스 루트 (dynamic import 대상). 스크롤→면 진행도, 클릭→방 진입 상태
src/components/home/book/BookPage.tsx       면 하나: 경첩 회전 + 판들
src/components/home/book/PaperLayer.tsx     판 하나: 텍스처 plane + 경첩 회전(open 진행도)
src/components/home/book/Jail.tsx           경첩 감옥 (빗금 텍스처 3종 스왑)
src/components/home/book/RoomPlates.tsx     명패 HTML 버튼 (판 좌표를 화면 좌표로 투영해 배치)
src/components/home/book/RoomPanel.tsx      방 정보 패널 HTML (home-paper). props: room, children(서버가 채운 내용)
src/components/home/book/BookFallback.tsx   폴백: 면 1 정지 이미지 + 공간 8곳 목록 링크
src/components/home/book/useBookScroll.ts   스크롤 → {pageIndex, t} (rAF·passive)
src/components/home/book/cameraPaths.ts     정면·방별 돌리 인 좌표, easing
```

- 홈 `page.tsx`: 기존 `DeskHero` 자리를 `PopupBook`으로 교체. `CalendarSection`·새 소식·오시는 길은 책 아래 그대로 유지(§3-1).
- 방 정보 패널 내용은 서버 컴포넌트가 `RoomPanel` children으로 넣는다(예: 사무소 = 설화 첫 컷 + `/about` 링크, 감옥 = 오늘 출근 요괴 목록).
- 상태는 컴포넌트 로컬(`useState`)+URL 해시. Zustand 불필요.

### 5-3. 성능 예산

| 항목 | 예산 |
|---|---|
| 초기 로드 (JS) | three+R3F+drei ≈ 150KB gz, 홈에서만 |
| 초기 텍스처 | 표지 + 면 1 전부 ≤ 1.5MB. 면 2·3·방 내부는 면 전환 직전에 프리로드 |
| 텍스처 크기 | 판당 최대 1024², 뒷배경 2048×1024 |
| 드로우콜 | 면당 ≤ 40 |
| 프레임 | iPhone 12급 60fps, 저사양은 DPR 1로 낮춤 |
| LCP | 표지 정지 이미지를 `<img>`로 먼저 그려 LCP 확보, 캔버스는 그 위에 페이드 인 |

### 5-4. 폴백·접근성

- WebGL 불가·`prefers-reduced-motion`·`navigator.deviceMemory < 2`·`saveData` → `BookFallback`(면 1 정지 이미지 + 8곳 목록). reduced-motion은 애니메이션만 끄고 펼쳐진 정지 상태로 두는 것도 허용.
- 명패는 `<button>`, 키보드 Tab 순서 = 스토리 순서, Esc로 방 나가기, 포커스는 패널 → 명패로 복귀.
- 캔버스는 `aria-hidden`. 모든 정보는 HTML에 있으므로 스크린리더는 3D 없이 완결.
- 이모지 금지(확정 선호). 명패·패널 문안은 한국어.

### 5-5. 제외

- 자유 시점·드래그 회전·마우스 오빗 (모바일 예산·명패 안정성)
- 사운드
- 원화에 없는 인물 앵글 생성
- 새 서브 페이지

## 6. 검증

- 실기기: iPhone(Safari)·Android(Chrome) 각 1대에서 열림 애니 60fps, 면 전환 끊김 없음, 명패 터치 성공

- 문안 금지 어휘 grep 0건
