# 나라카 공식 홈페이지 설계 (naraka-home)

> 2026-08-24 브레인스토밍·그릴 확정. 대구 동성로 요괴 컨셉카페 "나라카"의 정식 홈페이지를 만들고,
> 기존 나라카증권(주식 이벤트 앱)을 이벤트 하위 경로(`/event`)로 편입한다.

## 1. 목표와 배경

- 현재 `naraka.cafe` 루트는 8월 주식 이벤트 앱이 차지하고 있다. 이벤트는 2026-08-30 종료.
- 이후 `naraka.cafe`는 **카페 공식 홈페이지**가 되고, 주식앱은 `/event` 하위의 상설 이벤트 페이지가 된다.
- 구성 참고: maidreamin (TOP/LOCATION/ABOUT/MENU/MAIDS/TOPICS) — 디자인은 참고하지 않는다.
- 방문자에게 가장 먼저 보여야 할 정보(사장님 확정): **월간 이벤트데이 달력 + 요괴(스태프) 출근표.**

## 2. 구조·전환 계획

### 2.1 레포·브랜치

- 같은 레포에 통합. 레포명 `naraka-stock` → **`naraka-home`** 리네임 (`gh repo rename` + 로컬 remote 갱신, Vercel 연결 유지 확인). 리네임 시점은 구현 착수 시.
- 개발은 **전환 브랜치 `feat/naraka-home`** (main 기준)에서 진행. 진행 중 이벤트(~8/30)의 프로덕션은 무변경.
- Vercel 프리뷰 배포로 검증 후 **8/31 머지 = 전환**.

### 2.2 URL 구조 (전환 후)

| 경로 | 내용 |
|---|---|
| `/` | 카페 홈 (신규) |
| `/about` `/location` `/menu` `/staff` `/notice` `/events` `/games` | 카페 서브페이지 (신규) |
| `/event/*` | 나라카증권 — 기존 주식앱 페이지 전체 이동 (`/event/stocks/[code]`, `/event/portfolio` …) |
| `/api/*` | **변경 없음** — 페이지 라우트만 이동, API는 유지 → pg_cron 일일 배치·외부 호출 무영향 |

- 구 URL 리다이렉트: `next.config` redirects로 `/stocks/:path*` → `/event/stocks/:path*` 등 주식앱 전 페이지 매핑.
- 카페 홈은 `(home)` Route Group + 전용 레이아웃·팔레트. 주식앱 테마와 독립 (주식앱 UI는 현행 유지).
- 언어: 한국어 단일.

## 4. 홈 랜딩 — 인트로형 스크럽 여정

### 4.1 콘셉트

scroll-world(oso95/scroll-world) 방식의 **스크롤 스크럽 "날아 들어가는" 랜딩**. 실제 3D가 아니라
AI 생성 영상을 스크롤 진행도로 스크럽한다. Tripo 실시간 3D는 비채택 (앤틱 무드 재현·모바일 성능 리스크).

**인트로형** 확정: 여정은 홈의 연출 장치이며 탭 콘텐츠와 독립. 3~4장면으로 짧게.
잘 뽑히면 장면 추가 + 탭 CTA를 얹어 투어형으로 증축 가능한 구조로 만든다 (스크럽 엔진·장면 체인 구조 동일).

### 4.2 장면 구성 (4장면, 밤 무드 고정)

릴스 채용 설화 애니(별도 제작 중)와 **모티브만 공유** (소품 언어: 명패·이력서·도장·도깨비불·단체사진 액자). 컷 직접 재활용은 하지 않는다.

1. **마녀의 책상** — 명패 「@naraka_concafe」·이력서·도장·도깨비불 (릴스 엔딩과 대칭을 이루는 오프닝)
2. **단체사진 액자 속으로 다이브** — 카메라가 책상 위 액자를 통과해 들어간다
3. **카페 홀 통과** — 앤틱 홀(버건디 커튼·샹들리에·원목), 요괴들의 일상이 스쳐 간다
4. **게시판 도착** — 스크럽 종료, 실제 **달력·출근표 UI가 화면에 내려앉는 전환**

### 4.3 UX 안전장치

- 고정 헤더 내비 상시 노출 — 어떤 탭이든 항상 1클릭
- "건너뛰기" 버튼 — 달력·출근표 섹션으로 즉시 앵커 점프
- 재방문자는 localStorage로 기억해 여정 자동 축약 (읽기·쓰기 try/catch, 값 없으면 풀 여정)
- `prefers-reduced-motion` 시 정적 히어로 이미지 + 콘텐츠로 폴백
- 여정은 홈에만 존재. 서브페이지는 전부 일반 페이지

### 4.4 제작 파이프라인·분담 (2026-08-25 개정 — 릴스 재활용)

- **소스는 릴스 무성 애니** (별도 트랙, `~/Desktop/naraka/story/제작계획.md`: 치비 원화 17장 + Seedance 2.0 + AE, 9:16 29컷). 신규 장면 생성 없음.
- **웹 여정 = 릴스 구간 발췌**: 프롤로그 컷 1 + 엔딩 컷 29 **역재생**("책상→액자→단체샷" = 액자 다이브와 동일 연출) + 막별 대표 1~2컷. 발췌 10~15초 → ffmpeg WebP 프레임 시퀀스 → canvas 스크럽 (10MB 예산 내). 릴스 전체는 `/about` 임베드.
- **데스크톱 처리: 플랫 컬러 심리스 확장** — 9:16 영상 양옆을 각 장면의 플랫 배경색으로 CSS 확장 + 경계 그라데이션 마스크 (치비 플랫 그림체 전용 기법). 안 예쁠 경우 폴백 = 액자 무대.
- 릴스가 준비되기 전에는 stills 크로스페이드 모드(원화 크롭)로 우선 오픈 가능 — 엔진 겸용.
- **주의**: 외주 작가 동의(2차적저작물·AI 입력)에 웹사이트 사용 포함해 확인.

## 5. 달력 + 출근표 (홈의 핵심 정보)

- **월간 달력 통합형**: 날짜 칸에 이벤트데이 표시 + 그날 출근 요괴 아바타(치비) 함께 표시. 오늘 강조
- **하루 안 시간대 분할 지원**: 스태프별 출근이 하루 안에서도 나뉜다 → 날짜 클릭 시 그날 상세(이벤트 내용 + 시간대별 출근 타임라인)
- 데이터 소스: 이벤트 글(`home_posts` type=event)의 날짜/기간 + `home_schedule`

## 6. 데이터 모델·어드민

신규 테이블 (공개 읽기 RLS + 어드민 쓰기, 기존 Supabase·어드민 콘솔 확장):

```
home_posts       -- 공지·이벤트 통합
  id, type ('notice'|'event'), title, body_md, cover_image_url?,
  pinned, published_at, event_start_date?, event_end_date?   -- 날짜는 이벤트만

home_staff       -- 스태프 프로필
  id, name, role, photo_url?, intro, sort_order, is_active

home_schedule    -- 출근표 (시간대 분할: 같은 날 여러 행 허용)
  id, work_date, staff_id(fk), start_min, end_min

home_menu_items  -- 메뉴
  id, category, name, price(int), description, image_url?, sort_order, is_sold_out
```

- 어드민: 기존 `/admin` 콘솔에 "홈 콘텐츠 관리" 섹션 추가 — 공지/이벤트 작성(마크다운), 메뉴 CRUD, 스태프 CRUD, 출근표 주 단위 입력
- 이미지 업로드: **Supabase Storage 활성화** (현재 로컬 config.toml 비활성 → 활성 + prod 설정), 공개 버킷 `home-assets`
- 게임 허브는 초기 DB 불필요 (코드 정의 목록)
- 자산·금액 규칙 등 기존 주식앱 아키텍처 원칙은 홈과 무관 — 홈은 읽기 중심 콘텐츠 사이트

## 8. 리스크·주의

- **이벤트 진행 중(~8/30) 프로덕션 무변경** — 전환 브랜치는 8/31 이후에만 머지
- 주식앱 페이지 이동 시 내부 하드코딩 링크(`/stocks/...`, `/login` 등) 전수 수정 + 리다이렉트 검증 필요
- pg_cron 배치는 `/api/*` 유지로 무영향이지만, 전환 배포 후 배치 1회 정상 동작 확인
- 장면 간 연결 프레임 불일치가 이 기법 최대 리스크 — 장면 수를 3~4개로 유지, 연결 실패 시 크로스페이드 폴백
- `feat/hanji-theme` 작업(주식앱 한지 테마)은 별도 트랙 — 본 작업과 독립적으로 진행/병합
